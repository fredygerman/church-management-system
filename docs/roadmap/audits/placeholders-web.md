# Web app placeholder audit (apps/web) — read-only

Branch: `design/mito-ya-baraka-concepts` (working tree has uncommitted changes; findings reflect files on disk on 2026-11-27). Scope: `apps/web/app`, `apps/web/components`, `apps/web/lib`, `apps/web/config`, `apps/web/actions` and `apps/web/hooks` (tests excluded). API and shared-package reads only where they confirm a backing endpoint. No source was changed.

Goal: find every placeholder a user could mistake for a real feature. Input `placeholder=` attributes are excluded.

Method: grep of `onClick` and `onSubmit`/form actions; `toast.success` calls checked for a preceding request; mock-module imports; every sidebar route (`config/sidebar.ts`) and every hard-coded `/dashboard`, `/portal`, `/docs`, `/support` href checked against `app/[churchId]/…/page.tsx`; `.catch(() => …)` fallbacks; `disabled` controls; English copy in `packages/config/src/i18n/messages` for "not available / coming / yet" wording; `apps/api/src` for each backing route.

Evidence labels: all items are **verified** by reading the cited lines. Impact: High = a user is misled or blocked on a visible path; Medium = misleading in some states or a visible placeholder; Low = cosmetic or dead code. Effort: S ≤ 1 day, M 2–5 days, L > 1 week.

## 2) Ten most important items

1. **PH-WEB-01** — `/support` shows an empty "Contact Channels" section and promises email, phone, support hours and a 24-hour reply. None of it exists.
2. **PH-WEB-02** — the only contact path (`/support` form) is disabled, and the intake endpoint is a 503 stub.
3. **PH-WEB-03** — Attendance V2 "Branch" option shows zone data under a branch label. The analytics page already avoids this.
4. **PH-WEB-05** — Attendance V2 shows 0 sessions and 0 members when the request fails.
5. **PH-WEB-04** — AI assistant forms and confirm buttons are displayed but cannot run; the registry is empty by design (DEC-08).
6. **PH-WEB-06** — 13 list and dashboard page files show "empty" when the API fails; this extends WD-24.
7. **PH-WEB-07** — `/docs` is generic developer-platform copy with dead quick links and dead link-style buttons, and it links to four routes that do not exist.
8. **PH-WEB-08** — every tenant's sidebar footer reads "Mito Ya Baraka Church".
9. **PH-WEB-09** — users without a photo see a stock third-party portrait as their avatar.
10. **PH-WEB-13** — "Attendance V2" is a permanent nav label for a prototype.

## 3) Checked and not counted as placeholders

- `apps/web/app/[churchId]/dashboard/home/page.tsx`: real stats, with a proper unavailable state.
- `app/[churchId]/dashboard/content/staff-documents.ts`, library, offerings and member "unavailable" states: real failure states with real endpoints, not feature placeholders.
- `app/[churchId]/dashboard/analytics/page.tsx` and `lib/report-catalog.ts`: lists only reports with a verified source (DEC-04).
- `app/[churchId]/dashboard/communications/templates/page.tsx` `sample = '{{first_name}}'`: example text, not placeholder content.
- Sidebar hrefs (39 literal paths): every target page exists. The one apparent miss, `/auth/profile` in `app/setup/page.tsx:17`, is an API path (`apps/api/src/auth/auth.controller.ts:114`), not a web route.
- `app/[churchId]/portal/inbox`, `portal/library/resources`, `portal/church`, `components/portal/event-rsvp.tsx`, `components/invitations`, `components/zone`, `components/department`, `components/member`, all toolbar export actions, `auth/signin` (register toggle calls `/auth/register`), `dashboard-header` logout: all call real handlers.
- `toast.success` calls: every one in scope follows an awaited request or a server action result. None is toast-only.
- `components/announcements/*` and `packages/config/src/i18n/messages/announcements-web.ts` (`announcements.channels.unavailable`, "Not available yet."): uncommitted in-progress work. The channel section is not rendered by any web component yet, so it is not a user-visible placeholder. Re-audit once committed.
- `profile.email.readOnly` copy is used only in mobile (`apps/mobile/app/(member)/(tabs)/profile.tsx`); web does not show an email field, so there is no web placeholder.

## 4) Method limits

- Static read only. No browser or running app was used. Dynamic behaviour (for example the `/support` disabled state with real navigation) was not exercised.
- Silent-fallback list in PH-WEB-06 comes from grep of `.catch(() => …)`; it may miss fallbacks written as `try/catch`.
- Mobile app and `apps/api` internals were read only to confirm backing; they are not audited here.
