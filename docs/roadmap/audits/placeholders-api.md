# API placeholder audit (apps/api/src)

- Date: 2026-11-27. Branch: `design/mito-ya-baraka-concepts` (working tree, uncommitted). No source changed, nothing committed, no worktree.
- Scope: `apps/api/src`, excluding `*.spec.ts` and `testing/`. DB tables read from `packages/db/tables` only to check whether they are written.
- Method: grep for TODO/stub markers, literal returns, hard-coded values, log-only handlers, one-line function bodies, tables with no insert/update, and unused DTO/column fields. Each suspicious file was opened and confirmed before listing. Legitimate states (real empty lists, validation errors, 404s, documented zero values) are excluded.
- Caveats: static read only. No tests run, no live calls. Line numbers match the current working tree and may drift.
- Note: `announcements/`, `announcement-attachments/` and `verses/` are untracked, in-progress code. Their findings describe the uncommitted state.
- Related existing items in `docs/roadmap/audits/backend-api.md` and `infra-ops.md` are cross-referenced where they overlap (BE-04, BE-13, BE-17, BE-19, BE-29, IO-07).

## 3. Ten most important items

1. **PH-API-01** Password recovery sends nothing, so locked-out users cannot reset.
2. **PH-API-02** Scheduled announcements never publish.
3. **PH-API-03** Announcement publish returns 202 but SMS, email and push are never sent.
4. **PH-API-04** Milestone reminder rules are saved but never send anything.
5. **PH-API-05** Prayer requests are write-only; staff cannot see or answer them.
6. **PH-API-06** Campaign "delivered" and "bounced" counts are wrong or always zero.
7. **PH-API-07** Email campaigns are always skipped and end as failed.
8. **PH-API-09** The consent table is unused and SMS campaigns send with no consent check (legal).
9. **PH-API-08** The public church directory can never be populated.
10. **PH-API-10** QR check-in has no member-facing path.
