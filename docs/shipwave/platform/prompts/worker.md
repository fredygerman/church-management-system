# Worker prompt template

## Identity and outcome

Name the logical task, accepted owner, parent leader, assigned checkout/branch, owning spec, and measurable completion outcome. Worker model: Luna, subject to the accepted run proposal.

## Read first

Read repository instructions, programme run policy/backlog, owning spec, relevant product-design baseline and source paths. Verify facts before editing.

## Scope and rules

Work only in explicitly assigned paths. List shared files, exclusions, dependencies, and migration ownership. Shared checkout: do not create/use/switch worktrees. Never edit another group’s files, shared migrations, manifests, global config, or contracts unless explicitly assigned. Serialize generators, shared checks and commits. Preserve unrelated work. No visual checks, push, deploy, migration application, store setup, or unapproved provider/payment choice.

## Acceptance and evidence

Complete every acceptance row and relevant guard test. Search changed route, permission, locale, component and contract symbols across tests; report commands, exit codes, fresh log paths and test counts. Update owning spec, backlog and portable handoff. Append out-of-scope defects to incidental findings. Commit only if future run authorization explicitly includes commits; otherwise leave a reviewable diff.

## Final report

Report state, summary, changed paths, commit if authorized, checks with observed results, migration impact, remaining human verification, risks, blocker and one coordinator action. Do not claim checks or approvals not observed.
